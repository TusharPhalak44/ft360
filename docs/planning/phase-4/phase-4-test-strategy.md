## 2. Detailed Test Specifications (`All Cases: PLANNED — NOT EXECUTED`)

### 2.1 Unit Test Suite (`UT-P4-01` – `UT-P4-08`)
- **`UT-P4-01` (Slug Syntax & Reserved Denylist — `PLANNED — NOT EXECUTED`):** Verifies valid slugs (`acme-cloud`, `org-2026`), rejects uppercase/spaces/leading-or-trailing hyphens/`<3`/`>63` chars, and maps reserved words (`admin`, `api`, `auth`, `platform`, `workspace`, `portal`, `www`, `mail`, `status`, `health`, `docs`, `static`, `assets`, `billing`, `support`, `system`, `root`) to uniform `available: false`.
- **`UT-P4-02` (Exhaustive 6-State Lifecycle Matrix & `OD-P1` Cancellation Rule — `PLANNED — NOT EXECUTED`):** Tests every `(fromStatus, action, targetStatus)` tuple across `PROVISIONING`, `TRIAL`, `ACTIVE`, `SUSPENDED`, `DEACTIVATED`, and `CANCELLED` (verifying `CANCELLED` rejects all outbound transitions, direct `TRIAL -> CANCELLED` and `ACTIVE -> CANCELLED` fail `409` per confirmed `OD-P1`, self-transitions fail `409`, `SUSPENDED -> TRIAL` requires `activated_at IS NULL`, and `reason` requires `10–500` trimmed chars).
- **`UT-P4-03` (`sharp` Raster Image Decoding, Pixel-Bomb & Metadata Stripping — `PLANNED — NOT EXECUTED`):** Verifies valid `PNG`/`JPEG`/`WebP` logos and `PNG`/`WebP` favicons decode cleanly through `sharp` and strip embedded `EXIF`/`GPS`/`XMP`/`tEXt` metadata, while rejecting `.svg` (`415`), `.svg` renamed `.png` (`415`), HTML polyglots (`415`), oversized buffers (`413`), oversized dimensions/pixel-bombs (`> 2048x2048` / `> 4.19 MP` logo; non-square or `> 512x512` / `> 0.26 MP` favicon -> `422`), and truncated/corrupt pixel streams (`422`).
- **`UT-P4-04` (Settings & Profile DTO Validators — `PLANNED — NOT EXECUTED`):** Validates IANA timezones, BCP-47 locales, ISO-4217 currencies, ISO-3166-1 alpha-2 countries, E.164 phones, `invitationExpiryHours` (`1..720`, default `168` per `D3`), and `allowMemberDirectoryView` (`default false` per `D4`).
- **`UT-P4-05` (Audit Diff Calculation & Recursive Secret Redaction — `PLANNED — NOT EXECUTED`):** Verifies `computeFieldDiff(before, after)` emits only changed keys and recursively rejects/redacts forbidden keys (`password`, `token`, `tokenHash`, `encryptedActionToken`, `cookie`, `authorization`) inside nested objects and arrays.
- **`UT-P4-06` (Tenant Storage Key Isolation — `PLANNED — NOT EXECUTED`):** Confirms `buildBrandingStorageKey(tenantId, assetKind, ext)` enforces UUID format, ignores original client filenames (`../../etc/passwd`), and outputs `tenants/{tenantId}/branding/{assetKind}/{uuidv7}.{ext}`.
- **`UT-P4-07` (`TenantPermissionGuard` & `TenantAdminGuard` Evaluation — `PLANNED — NOT EXECUTED`):** Unit-tests explicit permission checks across all `24` canonical permissions (including `tenant:roles:assign`, `tenant:admins:read`, `tenant:admins:manage`, `tenant:invitations:read`, `tenant:invitations:manage`, `tenant:settings:read/manage`, `tenant:branding:read/manage`, `audit:tenant:read`).
- **`UT-P4-08` (Redis Outage Fallback vs Fail-Closed Policy — `PLANNED — NOT EXECUTED`):** Verifies `RedisSessionCacheService` and tenant cache wrappers catch connection errors, emit `REDIS_UNAVAILABLE_FALLBACK_PG` with `correlationId`, and delegate cleanly to PostgreSQL—while `slug-availability` rate limiter fails closed (`503`) when Redis throws.

### 2.2 Database, Concurrency & RLS Integration Suite (`DB-P4-01` – `DB-P4-07`, `RLS-P4-01` – `RLS-P4-06`)
- **`DB-P4-01` (Migration `0007`–`0008` Forward, Rollback & Re-Apply — `PLANNED — NOT EXECUTED`):** Applies `0007` and `0008` atop `0001`–`0006`, rolls back `0008 -> 0007 -> 0006` cleanly with zero orphaned objects, and re-applies `0007`–`0008` idempotently.
- **`DB-P4-02` (`22`-Table Ownership, `FORCE RLS` & `24`-Permission Seed Check — `PLANNED — NOT EXECUTED`):** Queries `pg_class`, `pg_tables`, and `public.permissions` to verify all `22` public tables are owned by `ft360_migrator` (`0` owned by `ft360_app`) with `relrowsecurity = true` and `relforcerowsecurity = true`, and all `24` permissions satisfy `chk_permissions_code_format`.
- **`DB-P4-03` (Composite Foreign Key Cross-Tenant Rejection — `PLANNED — NOT EXECUTED`):** Verifies cross-tenant `(tenant_a, tenant_b_*)` inserts/updates on `tenant_invitations`, `tenant_branding_settings`, `tenant_profiles`, `tenant_onboarding_states`, `tenant_audit_logs`, and `auth_email_outbox` fail with `23503`.
- **`DB-P4-04` (Serialized `FOR UPDATE` Last-Admin Lock & Internal-Only Admin Trigger — `PLANNED — NOT EXECUTED`):** Verifies `trigger_enforce_admin_membership_type()` blocks `CLIENT_PORTAL`/`PARTNER` `tenant_admin` assignments (`42501`), and `trigger_prevent_last_tenant_admin_removal()` serializes concurrent two-admin demotion/suspension transactions via `SELECT ... FROM public.tenants FOR UPDATE` so one commits and the second fails with `42501`.
- **`DB-P4-05` (`tenant_audit_logs` Immutability, `ON DELETE RESTRICT` & Secret Check — `PLANNED — NOT EXECUTED`):** Verifies `UPDATE` and `DELETE` fail with `42501` (even under `PlatformAdmin` GUC), deleting a referenced tenant fails `23503`, and nested secret keys fail `23514`.
- **`DB-P4-06` (Initiator vs. Recipient Schema Invariants on `auth_email_outbox` & `tenant_invitations` — `PLANNED — NOT EXECUTED`):** Verifies `chk_auth_email_outbox_anchor` enforces `user_id NOT NULL AND initiated_by_user_id IS NULL` for `'EMAIL_VERIFICATION'`/`'PASSWORD_RESET'` while requiring **`user_id IS NULL` and `(tenant_id, invitation_id) IS NOT NULL`** for `'TENANT_INVITATION'` (`23514` if initiator `user_id` is passed into `user_id`), and verifies `chk_ti_pending_recipient_unbound` and `chk_ti_initiator_recipient_distinct` (`accepted_by_user_id <> invited_by_user_id`).
- **`DB-P4-07` (Duplicate Global Email Database Unique Constraints & Concurrent Registration Race — `PLANNED — NOT EXECUTED`):** Executes parallel PostgreSQL transactions (`Promise.all` over separate pooled connections) attempting simultaneous `fn_invitation_accept_new_user` and `fn_auth_register_user` / raw `INSERT INTO public.users` calls for case/whitespace variants (`'Alice@Corp.com'`, `' alice@corp.com '`, `'ALICE@CORP.COM'`), asserting `uq_users_email`, `chk_users_email_canonical_trimmed`, `uq_users_email_normalized`, and `pg_advisory_xact_lock` allow **at most `1` row in `public.users`** (`SQLSTATE 23505` / `23514` on losers) while preserving losing `PENDING` invitations unburned.
- **`RLS-P4-01..06` (Unscoped Denial, Cross-Tenant Isolation, PostgreSQL Lifecycle Write-RLS, `token_hash` Omission & Unweakened `users_select` — `PLANNED — NOT EXECUTED`):** Under `ft360_app`, proves: (1) missing GUC returns `0` rows across all `7` new tables; (2) Tenant A cannot `SELECT`/`UPDATE`/`DELETE` Tenant B rows on any table; (3) `SELECT token_hash FROM tenant_invitations` fails `42501`; (4) `fn_is_current_tenant_operational()` + `fn_assert_tenant_operational()` block tenant writes and invitation operations inside PostgreSQL when `tenants.status` is `PROVISIONING`, `SUSPENDED`, `DEACTIVATED`, or `CANCELLED` (even with zero Redis connectivity); (5) `users_select` still hides unaccepted `INVITED` global users while `fn_tenant_list_workspace_members` returns `SUSPENDED`/`REVOKED` rows only to verified `tenant:members:manage` callers; and (6) pooled socket rollback leaks `0` rows.
